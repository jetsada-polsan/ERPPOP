# Bplus Table Scope Policy

วันที่: 2026-07-30

## หลักการ

ERP ใหม่จะเก็บเฉพาะโครงสร้างและข้อมูลที่จำเป็นต่อการทำงานของ PopStar ERP/POS เท่านั้น ไม่สร้างตาราง Bplus ทุกตารางตามจำนวนเดิม เพราะจะเพิ่มภาระดูแลฐานข้อมูลและทำให้ขอบเขตข้อมูลไม่ชัดเจน

ฐานข้อมูล Bplus เดิมเป็นแหล่งอ่านอย่างเดียวสำหรับตรวจสอบและอ้างอิง ห้าม migration หรือคำสั่ง mapping ใดแก้ไขข้อมูลต้นฉบับ

## สถานะการคัดกรอง

- `mapped`: มีตารางเป้าหมายใน ERP ใหม่และมี mapping ที่รู้ความหมายทางธุรกิจแล้ว จึงเป็นกลุ่มเดียวที่มีสิทธิ์เข้าสู่ขั้นตอนนำเข้าข้อมูลหลังผ่าน UAT
- `needs_review`: ยังไม่ยืนยันว่าใช้งานจริงหรือยังไม่มีกฎแปลงข้อมูล ห้ามนำเข้าหรือสร้างตารางตามชื่อเดิมจนกว่าจะตรวจสอบกับผู้รับผิดชอบระบบ
- `excluded`: ตารางเทคนิค ตารางควบคุมระบบ และ physical monthly/archive tables ไม่สร้างซ้ำใน ERP ใหม่ เก็บไว้ในแหล่งเดิมหรือคลัง legacy แบบอ่านอย่างเดียวเมื่อจำเป็นต่อ audit

## กฎปัจจุบัน

ตารางต่อไปนี้ถูกคัดออกอัตโนมัติเมื่อ register schema:

- ตารางเทคนิค เช่น `BPLUSCURRENTUSER`, `BPLUSDELETELOG`, `BPLUSLICENSE`, `BPLUSSYNC`, `BPLUSVERSION`
- ตารางอัตโนมัติ/รายงานภายใน เช่น `AUTOREPORTD`, `AUTOREPORTH`, `AUTORUNCODE`, `AUTOUPDARPRB`
- ตาราง metadata หรือ control เช่น `BYDATANAME`, `CREDITS`
- ตาราง physical รายเดือนที่ชื่อขึ้นต้นด้วย `C`, `D`, `H`, `L`, `P` หรือ `S` ตามด้วยตัวเลข 6 หลัก เช่น `C260701`

กฎนี้ไม่ถือว่าตารางธุรกิจที่ยังไม่รู้การใช้งานเป็นตารางทิ้ง ข้อมูลเหล่านั้นจะอยู่ใน `needs_review` เพื่อให้ตรวจสอบก่อนตัดสินใจ ลดความเสี่ยงตัดข้อมูลขาย ซื้อ สต๊อก ลูกหนี้ หรือบัญชีที่ยังมีประโยชน์

## ขั้นตอนก่อนนำเข้าจริง

1. ตรวจสอบ mapping กับเอกสาร Bplus และตัวอย่างรายงานของ PopStar
2. ระบุ primary key, foreign key, หน่วย, วันที่, สถานะเอกสาร และกฎ posting ให้ครบ
3. ทำตัวอย่างนำเข้าบนฐานข้อมูลทดสอบและเทียบยอดกับระบบเดิม
4. ทำ UAT แยกตามซื้อ ขาย POS ขายหลังบ้าน สต๊อก ลูกหนี้ และบัญชี
5. จึงเลื่อนสถานะจาก `needs_review` เป็น `mapped` และนำเข้าเฉพาะข้อมูลที่ผ่านการอนุมัติ

## Phase 2: ซิงค์ Master Data แบบไม่ทับสต๊อกสด

คำสั่ง `etl:master-data --skip-stock-snapshot` ใช้ซิงค์แฟ้มหลักที่ผ่าน mapping แล้ว เช่น สินค้า หน่วย บาร์โค้ด คลัง ลูกค้า ผู้ขาย และพนักงานขาย โดยอ่านจาก Bplus และเขียนเฉพาะ ERP ใหม่

กรณีต้องการนำเข้าเฉพาะสินค้า ให้ใช้ `etl:master-data --products-only` ระบบจะทำเฉพาะหมวด ฝ่าย ยี่ห้อ หน่วย สินค้า และบาร์โค้ด และจะไม่อ่านหรือนำเข้าคลัง ลูกค้า ผู้ขาย หรือยอดคงเหลือ

ในช่วงที่ ERP ใหม่มีการขายหรือปรับสต๊อกอยู่ ห้ามใช้คำสั่ง ETL แบบปกติ เพราะขั้นตอน snapshot เดิมจะล้าง `stock_balances` ก่อนสร้างยอดใหม่จาก Bplus การรัน Phase 2 ให้ใช้ `--skip-stock-snapshot` จนกว่าจะมีรายงานกระทบยอดยอดคงเหลือและได้รับอนุมัติให้เปลี่ยนแหล่งอ้างอิง

## การตรวจสอบ

หน้า `Mapping Bplus -> ERP` แสดงจำนวนและสถานะของทุกตารางใน `legacy_table_mappings` เพื่อให้ตรวจสอบได้ว่าอะไรถูกนำเข้า อะไรยังรอตรวจ และอะไรถูกตั้งใจไม่นำเข้า
