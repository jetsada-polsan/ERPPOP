# BplusBack หลักการเทียบกับ ERPPOP

เอกสารนี้สรุปหลักการจากคู่มือ `BplusBack` ที่นำมาเทียบกับโครงสร้าง ERPPOP ปัจจุบัน ใช้เป็น checklist สำหรับการเติมระบบโดยยึด flow จริงของ POPSTAR ไม่ใช่การคัดลอกหน้าจอของโปรแกรมเดิม

## หลักการที่ต้องรักษา

1. เอกสารทุกชนิดต้องมีสถานะ: ร่าง, รอตรวจ, อนุมัติ, ยืนยัน, ยกเลิก และต้องมีประวัติผู้ทำรายการ
2. เอกสารต้นทางต้องอ่านต่อไปเป็นเอกสารปลายทางได้ เช่น ขอซื้อ -> สอบราคา -> สั่งซื้อ -> รับสินค้า -> ตั้งหนี้ -> จ่ายเงิน
3. ทุกเอกสารต้องระบุผลกระทบชัดเจนว่าเพิ่ม/ลดสต๊อก, เพิ่ม/ลดลูกหนี้, เพิ่ม/ลดเจ้าหนี้, กระทบเงินสด/ธนาคาร และลง GL หรือไม่
4. ยืนยันเอกสารแล้วห้ามแก้ข้อมูลสำคัญตรง ๆ ต้องใช้เอกสารกลับรายการ/เอกสารแก้ไข และเก็บ audit log
5. มีรายงานตรวจสิ้นวัน, ตรวจความสัมพันธ์ระหว่างโมดูล และปิดต้นทุน/ปิดงวดก่อนออกงบ
6. รายงานต้องกรองได้อย่างน้อยตามช่วงวัน, สาขา, คลัง, ผู้ขาย/ลูกค้า, ผู้ทำรายการ, ประเภทเอกสาร และสถานะ

## เทียบตามโมดูล

สถานะ `มี` หมายถึงมี flow ใช้งานในระบบแล้ว, `บางส่วน` หมายถึงมีเอกสารหรือข้อมูลแต่ยังขาดปลายทาง/รายงาน/การแก้ไข, `ต้องเพิ่ม` หมายถึงยังไม่มี flow ครบพอที่จะใช้งานจริง

## ลำดับการเติมที่เหมาะกับ POPSTAR

### ระยะที่ 1: ปิดช่องว่างซื้อ-ขาย-สต๊อก

- ใบขอซื้อและใบสอบราคา พร้อมอ่านต่อเป็น PO
- ใบปรับต้นทุนรับที่ผูกกับ lot/สินค้าที่รับจริง
- รายงานรับ-ซื้อ-คืน-สั่งซื้อ และรายงานต้นทุน/กำไรจากเอกสารต้นทาง
- ใบเตรียมตรวจนับและผลต่างที่ต้องอนุมัติก่อนปรับสต๊อก
- สถานะค้างส่ง/ค้างรับ/ค้างชำระ และการแจ้งเตือน

### ระยะที่ 2: ปิดช่องว่างการเงิน

- AP voucher และ payment request/approval
- AR aging, ใบเตรียมรับชำระ และทะเบียนมัดจำ
- เอกสารฝาก/ถอน/โอนบัญชี และเช็คเด้ง/เปลี่ยนเช็ค
- รายงานค่าใช้จ่ายหลายมิติ: สาขา + รถ + Cost Center + บัญชี + โครงการ

### ระยะที่ 3: ปิดบัญชีและวิเคราะห์

- ตรวจความสัมพันธ์เอกสาร-สต๊อก-GL ก่อนปิดงวด
- recurring journal และ journal source trace
- report builder พร้อม drill-down และ saved filter
- หลายสกุลเงิน, budget variance, profitability และ anomaly alert

## เกณฑ์รับงานแต่ละฟังก์ชัน

ฟังก์ชันจะถือว่าเสร็จเมื่อผ่านครบ 6 ข้อ:

1. มีหน้าสร้าง/แก้ไข/ดู/พิมพ์ และสถานะเอกสาร
2. มีสิทธิและ approval ตามความเสี่ยง
3. ระบุผลกระทบต่อสต๊อก, AR, AP, เงินสด/ธนาคาร และ GL ได้
4. มีเอกสารต้นทาง/ปลายทางและ audit log
5. มีรายงานสรุปและ drill-down ที่ตรวจยอดกลับไปหาเอกสารได้
6. มี UAT กรณีปกติ, ยกเลิก, คืน, แก้ไข, ปิดงวด, duplicate และสิทธิไม่พอ

เอกสารนี้เป็น baseline ของงานเติมระบบ ไม่ได้หมายความว่าฟังก์ชันที่อยู่ในตารางสถานะ `บางส่วน` เสร็จเทียบเท่า BplusBack แล้ว ต้องทำ UAT ตามเกณฑ์ด้านบนก่อนประกาศพร้อมใช้งาน
