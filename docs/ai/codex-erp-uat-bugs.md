## บั๊ก
1. **ปุ่ม "ยืนยันรับสินค้า"** `resources/views/purchase-orders/show.blade.php:~314` ใช้ `onclick="return confirm(...)"` (native confirm ทำให้ automation ค้าง และไม่เข้ากับ UI) → เปลี่ยนเป็น modal ยืนยันแบบเดียวกับที่ระบบใช้ที่อื่น; ไล่หา `return confirm(` ทั้ง `resources/views` แล้วเปลี่ยนให้หมด (ใช้คอมโพเนนต์กลางตัวเดียว)
2. **ใบรับคืนสินค้า (sale return) เสนอคืนเงินเกิน**: บิลที่ออกใบลดหนี้ 5 บาทไปแล้ว ใบรับคืนยังเสนอคืน 20 เต็ม → ยอดคืนได้ต้อง = ยอดบิล − ใบลดหนี้/คืนที่ออกไปแล้ว (ทุกประเภท) ห้ามเกิน ทั้งค่าเริ่มที่เสนอและ validation ฝั่ง server (ส่งค่าเกินมาต้อง 422) ดู `resources/views/sale-returns/*`, controller/service ที่เกี่ยว
3. **สถานะดิบ "active"** โชว์ภาษาอังกฤษบนหน้าเอกสาร → แสดงป้ายไทยผ่าน helper/enum กลาง ไล่ทุกหน้าที่แสดง status ดิบ
4. **AP payment คอลัมน์เลขอ้างอิงแสดง "-"** ทั้งที่กรอกเลขอ้างอิงไว้ → แสดงค่าจริง (ตรวจว่าเก็บลงคอลัมน์ไหน)
5. **ฟอร์มปรับสต๊อก / เบิก / แปรรูป (transform) แสดงยอดคงเหลือหรือต้นทุนในระบบเป็น 0 หรือ "-"** ตอน preview → ดึงยอด/ต้นทุนจริงตามคลัง/สาขาที่เลือก
6. **header ทับชื่อหน้า** ในหน้าใบเสนอราคาและใบวางบิล → แก้ layout
7. **ใบลดหนี้ผู้ขาย (supplier notes) รายการต้นทางว่าง** เพราะกรองตาม branch ของผู้ใช้ (admin อยู่ B001 จึงไม่เห็นเอกสาร HQ) `app/Http/Controllers/SupplierNoteController.php:~21` → ใช้สิทธิ์สาขาตามระบบสิทธิ์จริง (ผู้มีสิทธิ์ทุกสาขาเห็นทุกสาขา, ผู้ใช้สาขาเห็นเฉพาะสาขาตน) และให้เลือกสาขาได้
8. **โอนเงินสด (cash transfers) ล็อกสาขาเป็น B001** → ผู้มีสิทธิ์หลายสาขาเลือกสาขาได้ ผู้ใช้สาขาเดียวล็อกตามเดิม; server ตรวจสิทธิ์สาขาเสมอ
9. **หน้า PLU เครื่องชั่ง** (`resources/views/scale-prices/index.blade.php` แท็บ PLU ปัจจุบัน) ตารางล้นขวาบนจอ ≤1024 คอลัมน์ "ปัญหา" ถูกตัด → ให้พอดีจอ (ย่อคอลัมน์/ห่อข้อความ/การ์ดบนจอแคบ)

หมายเหตุ: "ไม่มีบัญชีธนาคารก่อนทดสอบ" เป็นเรื่องข้อมูล ไม่ต้องแก้โค้ด
