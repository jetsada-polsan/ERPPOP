# Codex: หน้าตั้งค่า PLU เครื่องชั่ง — แจ้งปัญหาทุกแถว + แก้ได้ในหน้าเดียว

Branch `claude/scale-plu-page` (จาก origin/main) commit เป็นขั้น push ได้ **ห้าม deploy ห้ามแตะ production**
migration ต้องรันได้ทั้ง SQLite และ PostgreSQL

## หลักของร้าน (เจ้าของยืนยัน)
- SKU สินค้าชั่งคือรหัสปกติ (10xxxx ฯลฯ)
- PLU `800xxx/801xxx` ต้องเป็น **รหัสลูก (product_barcodes, type SCALE_PLU) ใต้ SKU จริง** เท่านั้น
- ป้ายเครื่องชั่ง = PLU + ราคารวม → POS หาน้ำหนักจากราคา/กก. ใน ERP ⇒ ราคา ERP ต้องเท่าราคาในเครื่องชั่ง

## ข้อมูลจริงใน production ตอนนี้ (88 PLU) — ปัญหาที่หน้าต้องจับได้
ดูตัวอย่างเต็มใน `scale-plu-prod.txt` (คัดลอกไว้ที่ `docs/ai/scale-plu-prod.txt` — ข้อมูลจริง ห้าม commit ไฟล์นี้)
1. **SKU เป็นเลข PLU เอง** (sku_code == barcode เช่น 801003) 31 ตัว → ผิดหลัก ต้องย้ายไปใต้ SKU จริง
2. **SKU แม่ปิดใช้งาน** (products.is_active = false) 43 ตัว → POS ไม่ sync สินค้า ยิงป้ายแล้ว "ไม่พบสินค้า"
3. **SKU เดียวมีหลาย PLU** เช่น SKU 801021 (หมูกระทะ) มีทั้ง 801021 และ 801081 แต่ป้าย 801081 คือ "ขาหลังหมู" → ต้องเตือน
4. **PLU ซ้ำ** (barcode เดียวอยู่หลายสินค้า) → เตือนแดง
5. **ราคา ERP ≠ ราคาเครื่องชั่ง** เช่น ตับหมู ERP 89 แต่เครื่องชั่ง 100
6. ยังไม่ตั้งราคา (≤ 1)
7. สินค้าชื่อมี ชั่ง/ซั่ง แต่ไม่มี PLU (ข้อมูล ไม่ใช่ error)

## ทำอะไร (แก้ `ScalePriceController` + `resources/views/scale-prices/index.blade.php` + routes เดิม)
- รายการหลัก = **ทุก PLU 800/801 ที่ลงทะเบียน** (รวมที่สินค้าปิดใช้งาน) + สินค้าชั่งที่ยังไม่มี PLU
- คอลัมน์: PLU | SKU แม่ + ชื่อ + สถานะเปิด/ปิด | ราคา ERP/กก. (แก้ได้) | **ราคาในเครื่องชั่ง/กก.** (กรอกได้ เก็บไว้) | ปัญหา (badge สี + ข้อความไทยสั้นๆ บอกวิธีแก้) | ปุ่มจัดการ
- เก็บราคาในเครื่องชั่ง: migration ใหม่ เช่นคอลัมน์ `scale_price` (decimal nullable) บน product_barcodes หรือ table `scale_plu_settings(barcode unique, scale_price, updated_by)` — เลือกแบบที่ไม่กระทบ ETL/BPlus
- นำเข้าราคาเครื่องชั่ง: วาง/อัปโหลด CSV `PLU,ราคา/กก.` ได้ทีเดียว (preview ก่อนบันทึก)
- **ย้าย PLU ไปใต้ SKU** (product picker ที่มีอยู่ `partials/product-picker`): เปลี่ยน product_id ของ barcode แถวนั้น, ตั้ง type SCALE_PLU, ห้ามสร้างเลข PLU ใหม่ (กติกาเดิม attachPlu), บันทึก audit (มี activity/audit log ในระบบอยู่แล้วให้ใช้), ยืนยันก่อนย้าย, กันย้ายไปสินค้าที่ปิดใช้งาน
- ด้านบน: การ์ดสรุปจำนวนแต่ละปัญหา คลิกแล้วกรอง, ช่องค้นหา PLU/SKU/ชื่อ, แท็บ "มีปัญหา / ทั้งหมด / ปกติ" (default = มีปัญหา)
- ปุ่ม "ทดสอบป้าย": วางบาร์โค้ดป้าย 13 หลัก → แสดงผลแบบเดียวกับ POS (profile จาก `scale_barcode_profiles`, check digit, PLU, ราคารวม, สินค้าที่เจอ, น้ำหนักที่ได้ = ราคารวม ÷ ราคา ERP) และเตือนถ้าน้ำหนักเพี้ยนเพราะราคาไม่ตรง
- export CSV เดิมคงไว้ + เพิ่มคอลัมน์ปัญหา
- ใช้งานง่ายบนจอเล็ก ใช้สไตล์/คอมโพเนนต์เดิมของ layout (content-card, badge, Alpine) ภาษาไทยทั้งหมด
- สิทธิ์: ใช้ permission เดิมของหน้านี้ (ดู ErpAuthorize/route map) การย้าย PLU/แก้ราคา ต้องสิทธิ์จัดการข้อมูลหลัก
