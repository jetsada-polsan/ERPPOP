# การทำงานร่วมกันระหว่าง Codex กับ Claude

ไฟล์นี้เป็นกติกากลาง โดยมี `docs/ai/PROJECT_MEMORY.md` เป็นสถานะและบริบทร่วมล่าสุด
ทั้ง Codex และ Claude ต้องอ่านสองไฟล์นี้ก่อนเริ่มงาน

## ลำดับงาน

1. เจ้าของโปรเจกต์มอบหมายงานให้ Codex หรือ Claude เพียงหนึ่งฝั่งต่อครั้ง
2. Agent ที่รับงานทำ `git checkout main && git pull origin main` ก่อนเริ่ม
3. แก้โค้ดและทดสอบตามขอบเขต
4. Commit, push `main`, และบันทึก handoff ใน `docs/ai/task.md`
5. Agent ถัดไป pull ก่อนเริ่ม และตรวจ/ทำงานต่อจาก commit ล่าสุด
6. Deploy เฉพาะเมื่อเจ้าของโปรเจกต์อนุญาต

## กฎที่ห้ามข้าม

**ห้ามทำงานพร้อมกันบนไฟล์หรือ branch เดียวกัน** ทุกครั้งต้อง push แล้ว pull รับไม้ต่อ

**การ review แยกยังควรทำกับงานเสี่ยงสูง** เช่น POS checkout, สต๊อก, ราคา, migration,
บัญชี, สิทธิ์ และ deployment แต่เจ้าของสามารถสั่งให้ Claude หรือ Codex แก้ตรงได้

**ไม่มีใครตั้งรหัสผ่าน PIN หรือออก token ให้** ทั้งสองฝั่งเตรียมคำสั่งให้เจ้าของโปรเจกต์รันเอง
เพราะค่าพวกนี้ถ้าผ่านหน้าจอแชทถือว่ารั่วแล้ว

## รูปแบบ `docs/ai/claude-review.md` (Claude เขียน)

เขียนทับไฟล์เดิมทุกรอบ ประวัติรอบก่อนดูจาก git history

```markdown
# ผลตรวจ — <วันที่>

## ช่วง commit ที่ตรวจ
<hash>..<hash>

## สรุป
ผ่าน / ต้องแก้ก่อน push

## สิ่งที่รันจริง
- คำสั่ง + ผลลัพธ์ที่ได้จริง (ไม่ใช่ที่คาดว่าจะได้)

## สิ่งที่พบ
### 1. <หัวข้อ> — ต้องแก้ / ควรแก้ / ข้อสังเกต
- ไฟล์: `path/to/file.php:123`
- อาการ: เกิดอะไรขึ้นเมื่อไหร่
- เสนอ: แก้ยังไง

## ที่ตรวจแล้วไม่มีปัญหา
- ระบุขอบเขตที่ดูจริง เพื่อให้รู้ว่าอะไร "ยังไม่ได้ดู"
```

ระดับความรุนแรงใช้แค่ 3 ระดับ **ต้องแก้** (ห้าม push), **ควรแก้** (push ได้ แต่ทำต่อ),
**ข้อสังเกต** (ไว้พิจารณา)

## สิ่งที่ต้องรันทุกรอบตรวจ

```bash
php artisan test                                    # ต้องผ่านทั้งหมด
cd apps/pos-desktop && ./node_modules/.bin/vue-tsc --noEmit   # ถ้าแตะแอป POS
```

ถ้าแก้เรื่อง migration ให้ดูด้วยว่ารันได้ทั้ง SQLite (เทสต์) และ PostgreSQL (production)
เพราะเทสต์ใช้ SQLite in-memory แต่ของจริงเป็น PostgreSQL — บางไวยากรณ์ผ่านที่หนึ่งแต่พังอีกที่

## รู้ไว้จะได้ไม่เสียเวลา

- **เทสต์ผ่านไม่ได้แปลว่าถูก** `enforcedCashierId()` ใน `PosController` อ่าน `request()` ตัวกลาง
  ไม่ใช่ `$request` ที่ส่งเข้า action เทสต์ที่ไม่ `$this->app->instance('request', $request)`
  จะไปวิ่งเส้นทางเว็บแทนเส้นทางเครื่อง POS แล้วผ่านแบบผิดๆ
  วิธีพิสูจน์: ถอดโค้ดที่แก้ออกชั่วคราวแล้วดูว่าเทสต์แดงจริงไหม
- **Node ไม่ได้ติดตั้งบนเครื่อง** ยืมจาก `/Applications/Codex.app/Contents/Resources/cua_node/bin`
  `vue-tsc` รันได้ แต่ `vite build` พังเพราะ native module ของ rollup คนละ Team ID
- **PHP** เครื่อง 8.5 / server 8.3 — อย่าใช้ไวยากรณ์ที่มีเฉพาะ 8.4+
- ดูขั้นตอน deploy ที่ `docs/OPERATIONS.md`
