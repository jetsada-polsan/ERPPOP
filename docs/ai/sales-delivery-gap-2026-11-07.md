# ตรวจช่องว่างใบจอง แยกใบขาย และเอกสารส่งของ — 7 พ.ย. 2569

## ข้อเท็จจริงจากโค้ด

- `CreditSaleService::convertBookingToCreditSale` ล็อกใบจองและแปลงรายการทั้งหมดเป็นใบขายเชื่อใบเดียวใน transaction เดียว ตัดสต็อก ตั้งลูกหนี้ และลงบัญชี; `sale_bookings.confirmed_document_id` เก็บปลายทางใบเดียว
- ระบบคำนวณ VAT จาก `products.is_vat` และ `document_books.no_vat`; แฟ้มลูกค้ามีเลขภาษี แต่ยังไม่มีเงื่อนไขภาษีเริ่มต้นหรือเงื่อนไขการชำระที่ระบุในโจทย์
- หน้ารายละเอียดใบจองมีใบส่งของชั่วคราว A5 สองสำเนา; หน้าใบรวมจองกรองสาขา สายและวันที่เอกสาร มีใบขึ้นของและรวมสินค้า แต่ไม่ใช่ระบบเลือกรอบรถ/คนขับ/ใบจองเพื่อพิมพ์รวม และกรองวันที่เอกสาร ไม่ใช่วันที่นัดส่ง
- สถานะจัดส่ง/ใบขึ้นของมีบริการและชุดทดสอบอยู่แล้ว ควรต่อยอดของเดิม

## งาน P0 ที่ต้องทำก่อนใช้จริง

ตรวจตัวอย่าง Business Plus ผ่าน AnyDesk: DS และ DSN เป็นเล่มขายเชื่อทั้งคู่ เลขรันแยกตามเดือน; DS ตัวอย่างมียอดยกเว้น VAT จึงใช้ชื่อเล่มตัดสินภาษีไม่ได้. ตัวอย่าง DS และ DSN ของลูกค้ารายเดียวอ้างใบจองเดียวกัน แยกสินค้าคนละรายการ ใช้ข้อตกลงเงินสดและ N-เงินสดตามลำดับ และถูกอ้างจากใบรับเงินเดียวกัน. หลังรับชำระ/คืน ระบบเดิมไม่อนุญาตแก้รายการ. ยังต้องตรวจทะเบียนลูกค้า/สินค้าและกฎกำหนดเล่มจากข้อมูลจริงเพิ่มเติม

การเชื่อมไปหลายใบต้องปรับ `SaleController`, `FleetController`, `ReportController` และหน้ารายละเอียดใบจอง ซึ่งยังอาศัย `confirmed_document_id` ใบเดียว; ห้ามสร้างใบที่สองโดยไม่ปรับส่วนเหล่านี้ เพราะยอดรายงานและงานขนส่งจะไม่ครบ

1. ยืนยันความหมาย DS, DSN และเงื่อนไขเงินสด/เครดิตกับผู้ใช้งาน พร้อมตรวจเล่มเอกสารจริง; สถานะภาษีกับวิธีชำระเป็นคนละเรื่อง
2. ออกแบบความสัมพันธ์ใบจองหนึ่งใบต่อใบขายหลายใบ รักษาความเข้ากันได้ของ confirmed_document_id เดิม พร้อม migration ที่ย้อนกลับได้
3. แสดง preview กลุ่มภาษีจากสินค้าและเงื่อนไขลูกค้า อนุญาตเปลี่ยนเฉพาะกรณีที่ถูกต้องพร้อมสิทธิ์และ audit; ห้ามใช้ลูกค้าอย่างเดียวลบ VAT สินค้าที่ต้องเสีย
4. ยืนยันการแยกทั้งชุดใน transaction ล็อกใบจอง ตรวจแถวครบไม่ซ้ำ ตรวจยอดก่อน/หลัง สร้างเลขในเล่มที่ถูกต้อง ตัดสต็อก/ลูกหนี้/GL ครั้งเดียวต่อรายการ rollback ทั้งชุดหากล้มเหลว
5. ปรับเส้นทางค้นหาเอกสาร พิมพ์ รับชำระ คืนและยกเลิกให้สัมพันธ์กับใบปลายทางแต่ละใบ และป้องกัน retry ซ้ำ
6. ทดสอบผสม VAT/ยกเว้น VAT กลุ่มเดียว สองกลุ่ม รายการซ้ำ สต็อกไม่พอ งวดปิด retry การรับชำระ/คืน ความถูกต้อง GL และสิทธิ์; ทดสอบ SQLite และ PostgreSQL

## งานส่งของ

ต่อยอดใบรวมจองและบอร์ดขนส่ง โดยตรวจ branch permission และใช้วันที่นัดส่งจริง เลือกใบจอง/สาย/รอบ/คนขับจากข้อมูลเดิม พิมพ์ใบส่งของชั่วคราว ใบขึ้นของ ใบรวมสินค้า และใบปะหน้า โดยไม่ตัดสต็อกหรือบันทึกขายจากการพิมพ์; ออกแบบประวัติพิมพ์ซ้ำและสิทธิ์ก่อนเพิ่มฐานข้อมูล

## ข้อจำกัด

เอกสารนี้เป็นการตรวจเฉพาะโค้ดที่อ้างถึง ไม่ใช่ผลตรวจครบทุก Phase ใน master prompt และยังไม่ได้ยืนยันรูปแบบข้อมูลจริงหรือทดสอบ workflow บน production
