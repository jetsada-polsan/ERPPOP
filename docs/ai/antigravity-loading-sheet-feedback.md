## 1. สรุปภาพรวมการพัฒนา (Executive Summary)

ตามข้อเสนอแนะและปัญหาการใช้งานจริงจากฝ่ายขายกันทรลักษ์เกี่ยวกับการจัดของ การพิมพ์ใบขึ้นของ และการตรวจสอบยอดจองเทียบยอดขายเชื่อ ระบบได้รับการปรับปรุงใน 2 ส่วนสำคัญ:
1. **ปรับปรุงหน้าใบรวมจอง (`bookings.summary`):**
   - รองรับการสั่งพิมพ์แยกแต่ละส่วนได้อิสระ 3 ส่วน ("พิมพ์ใบขึ้นของ", "พิมพ์รายการสินค้าที่ต้องเตรียม", "พิมพ์ใบเช็คส่งของประจำสาย") โดยไม่กระทบปุ่มพิมพ์ทั้งหน้ารวมเดิม
   - ปรับหัวบิลของใบขึ้นของแต่ละใบ (`.load-bill-head`) ให้ตัวหนา ขนาด 16px (font-weight 800) และมีเส้นประคั่นชัดเจนระหว่างบิล พร้อมตารางขนาดตัวอักษรไม่ต่ำกว่า 13px ในโหมดพิมพ์
   - เพิ่มระบบค้นหาสินค้าแบบทันที (Real-time Filter) พร้อมตัวกรองสายขายและคลังสินค้าในส่วน "รายการสินค้าที่ต้องเตรียม"
   - คลิกแถวสินค้าเพื่อดู Drilldown แสดงรายละเอียดว่าสินค้านี้ถูกจองในใบจองใบไหนบ้าง ลูกค้าท่านใด คลังใด และจำนวนเท่าไร
   - เพิ่มคอลัมน์ "บาร์โค้ดหน่วยที่จอง" ที่สามารถเปิด/ปิดการแสดงผลด้วย Checkbox โดยคงรหัสสินค้า (`sku_code`) ไว้เหมือนเดิม
2. **เพิ่มรายงานใหม่ "เทียบใบจองกับใบขาย" (`bookings.comparison`):**
   - เปรียบเทียบยอดเงินรวมของใบจองกับใบขายเชื่อที่คอนเฟิร์มแล้ว (แยกตามใบ หรือหลายใบขายต่อหนึ่งใบจอง)
   - แสดงส่วนต่างและไฮไลต์สีเมื่อยอดไม่ตรงกัน
   - ระบุสถานะชัดเจน: *ยังไม่ออกบิล*, *ออกครบ*, *ออกบางส่วน*, *ยกเลิก*
   - แถวสรุปรวมทั้งหมด และปุ่มส่งออก CSV ที่มี UTF-8 BOM แสดงภาษาไทยถูกต้อง 100%

## 2. รายละเอียดการปรับปรุงตามคำขอของฝ่ายขาย (Feedback Implementation)

### 2.1 พิมพ์แยกแต่ละส่วนได้อิสระ (Separate Print Sections)
- **ปัญหาเดิม:** หน้า `bookings.summary` รวม 3 ส่วนไว้ด้วยกัน เมื่อกดสั่งพิมพ์จะพิมพ์ออกมาทั้งหมด ทำให้ฝ่ายจัดของและคนขับรถได้เอกสารยาวเกินความจำเป็น
- **การแก้ไข:**
  - เพิ่มปุ่มพิมพ์แยก 3 ปุ่มบน Toolbar ด้านบน และปุ่มพิมพ์ย่อยบนหัวการ์ดแต่ละส่วน:
    1. **"พิมพ์ใบขึ้นของ (ทีละบิล)"** (`printSection('bills')`)
    2. **"พิมพ์รายการสินค้าที่ต้องเตรียม"** (`printSection('items')`)
    3. **"พิมพ์ใบเช็คส่งของประจำสาย"** (`printSection('route')`)
    4. ปุ่มเดิม **"พิมพ์ใบรวมจอง"** (`printSection('all')`) ยังคงอยู่เพื่อพิมพ์ทั้งหน้า
  - ทำงานผ่าน JavaScript ตั้ง Class ที่ `<body>` (เช่น `print-section-bills`) ก่อนสั่ง `window.print()` และลบออกใน `afterprint`
  - ใช้ `@media print` ซ่อนส่วนที่ไม่เกี่ยวข้องอย่างสมบูรณ์
  - ปฏิบัติตามกฎ PR #45: สั่งซ่อน `.app-sidebar` เมนูข้างไม่ให้โผล่มาในหน้าพิมพ์อย่างเด็ดขาด (`html body .app-sidebar { display: none !important; }`)

### 2.2 ปรับหัวบิลตัวหนา ใหญ่ขึ้น และมีเส้นประคั่นชัดเจน
- **ปัญหาเดิม:** หัวบิลของแต่ละใบจองตัวเล็กและกลืนไปกับตาราง ทำให้พนักงานจัดของมองเห็นเลขที่บิลและชื่อลูกค้าไม่ชัดเจน
- **การแก้ไข:**
  - ปรับปรุง `.load-bill-head`:
    - เลขที่ใบจอง (`.load-bill-doc`): ตัวหนาพิเศษ 800 ขนาด 16px (17px บนหน้าจอ)
    - รหัสและชื่อลูกค้า (`.load-bill-customer`): ตัวหนา 800 ขนาด 16px
    - ยอดเงินใบจอง (`.load-bill-amount`): ตัวหนา 800 ขนาด 16px
  - เพิ่มเส้นคั่นระหว่างบิล: `border-bottom: 2px dashed #444` ในขณะพิมพ์ และ `#b8c7d6` บนหน้าจอ
  - กำหนดขนาดตัวอักษรในตารางขณะพิมพ์ `.summary-table th, .summary-table td`: ไม่ต่ำกว่า 13px (ตามมาตรฐานใบขึ้นของ BPlus เดิม) พร้อมตัดปัญหาขึ้นหน้าใหม่กลางบิลด้วย `break-inside: avoid; page-break-inside: avoid;`

### 2.3 ค้นหาสินค้า ตัวกรองสายขาย/คลังสินค้า และ Drilldown รายการจอง
- **ที่มาของข้อมูลในระบบ ERP:**
  - **สายขาย (Sales Area):** ดึงจาก `sale_bookings.sales_area_id` (หรือ `documents.sales_area_id`) เชื่อมไปยังโมเดล `SalesArea`
  - **คลังสินค้า (Warehouse):** ดึงจากรายการตัดสต็อกของใบจอง `stock_document_items.warehouse_location_id` เชื่อมไปยัง `WarehouseLocation` และ `Warehouse`
- **การทำงานของหน้าจอ:**
  - **แถบค้นหา (#prep-search):** พิมพ์รหัสสินค้า (`sku_code`) หรือชื่อสินค้า ระบบจะกรองแถวในตารางทันทีโดยไม่ต้องโหลดหน้าใหม่
  - **ตัวกรองสายขาย (#prep-area-filter):** เลือกสายการขายที่ต้องการดูสินค้า
  - **ตัวกรองคลังสินค้า (#prep-warehouse-filter):** เลือกคลังตัดสต็อก (เช่น "คลังหลัก", "คลังหน้าร้าน")
  - **คำนวณยอดรวมใหม่อัตโนมัติ:** เมื่อเลือกตัวกรองสายหรือคลัง ระบบจะคำนวณผลรวมจำนวนสินค้า (`total_qty`) ใหม่ตามรายการย่อยที่ตรงกับเงื่อนไขทันที
  - **Drilldown รายการใบจอง:** คลิกที่แถวสินค้าใดๆ หรือไอคอนลูกศร จะขยายแถบรายละเอียดด้านล่าง แสดงรายการใบจองทั้งหมดที่มีสินค้านี้ เลขที่ใบจอง, ลูกค้า, สายขาย, คลังตัดสต็อก และจำนวนที่จอง

### 2.4 คอลัมน์บาร์โค้ดหน่วยที่จอง (Toggleable Barcode Column)
- **ข้อกำหนด:** ห้ามเปลี่ยนรหัสสินค้าที่แสดงเดิม (`sku_code`) เนื่องจากฝ่ายขายยังไม่ยืนยันว่าจะเปลี่ยนเป็นแบบใด
- **การแก้ไข:**
  - แสดง `sku_code` ในคอลัมน์แรกเหมือนเดิมทุกประการ
  - เพิ่มคอลัมน์ "บาร์โค้ดหน่วยที่จอง" (`barcode-col`) ดึงจาก `product_barcodes` ตาม `unit_id` ของหน่วยในใบจอง (หรือบาร์โค้ดหลักของสินค้านั้น)
  - เพิ่ม Checkbox Switch **"แสดงบาร์โค้ดหน่วยที่จอง"** (`#toggle-barcode`) ให้ผู้ใช้เปิด/ปิดได้ตามต้องการ
  - คอลัมน์นี้จะซ่อนอยู่เป็นค่าเริ่มต้น และจะแสดงและพิมพ์ออกมาเฉพาะเมื่อผู้ใช้เลือกเปิดใช้งานเท่านั้น

### 2.5 รายงานใหม่: เทียบใบจองกับใบขายเชื่อ (`bookings.comparison`)
- **เส้นทาง (Route):** `GET /bookings/comparison` (`name: bookings.comparison`)
- **การเชื่อมโยงเมนู:** แสดงในแถบเมนูหลัก **ขาย / เอกสาร -> เทียบใบจองกับใบขาย** และมีปุ่มทางลัดในหน้า `bookings.index` และ `bookings.summary`
- **ตารางเปรียบเทียบประกอบด้วย:**
  1. ลำดับ
  2. เลขที่ใบจอง
  3. วันที่จอง
  4. ลูกค้า
  5. สายขาย
  6. ยอดใบจอง (`documents.total_amount`)
  7. เลขที่ใบขาย (ดึงจาก `$booking->saleDocuments()` รองรับทั้งกรณี 1 ใบจองแตกเป็นหลายใบขาย)
  8. ยอดใบขายรวม (ไม่นับใบขายที่ถูกยกเลิก/voided)
  9. ส่วนต่าง (`ยอดใบจอง - ยอดใบขายรวม`) คำนวณตรงตามสตางค์ ไฮไลต์พื้นสีแดงเมื่อมียอดต่าง
  10. สถานะ:
      - **ยังไม่ออกบิล:** ยังไม่มีใบขายเชื่อมโยง
      - **ออกครบ:** มีใบขายและยอดเงินตรงกัน (ส่วนต่าง = 0.00)
      - **ออกบางส่วน:** ยอดใบขายไม่เท่ายอดใบจอง (มียอดคงค้างหรือต่างกัน)
      - **ยกเลิก:** ใบจองถูกยกเลิก
  11. แถวสรุปรวมทั้งหมดท้ายตาราง
  12. ปุ่มส่งออก CSV (รองรับภาษาไทยด้วย UTF-8 BOM `\xEF\xBB\xBF`)

## 3. การควบคุมสิทธิ์และการจำกัดสิทธิ์ตามสาขา (Authorization & Branch Isolation)

1. **การควบคุมสิทธิ์:**
   - ใช้สิทธิ์ที่มีอยู่เดิมคือ `sales.manage` ซึ่งผูกกับ Route Group `bookings.*` ใน `App\Support\RoutePermissions` โดยไม่มีการสร้างสิทธิ์ใหม่
   - ผู้ใช้ที่ไม่มีสิทธิ์ `sales.manage` จะได้รับ HTTP 403 Forbidden ทันที
2. **การจำกัดการเข้าถึงตามสาขา (Branch Isolation):**
   - ใช้การตรวจสอบผ่าน `$user->canSeeAllReportBranches()`
   - หากผู้ใช้เป็นระดับสาขา (ไม่มีสิทธิ์ดูทุกสาขา) ระบบจะบังคับกรองข้อมูลเฉพาะ `branch_id` ของผู้ใช้นั้นอัตโนมัติ
   - หากผู้ใช้พยายามส่งพารามิเตอร์ `branch_id` อื่นผ่าน URL ระบบจะตัดสิทธิ์และส่ง HTTP 403 `ไม่มีสิทธิ์เข้าถึงสาขานี้` ทันที
