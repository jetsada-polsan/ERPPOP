# Codex รอบ 2: รันเลข PLU ใหม่ 801001 เรียงไป + หน้าแก้ไขง่าย (ต่อจากงานหน้า PLU)

เจ้าของร้านตัดสินใจแล้ว: **รันเลข PLU เครื่องชั่งใหม่ทั้งชุด เริ่ม 801001 เรียงไป** แล้วไปตั้งเครื่องชั่งตามไฟล์ที่ระบบออกให้
ทำต่อบน branch เดิม `claude/scale-plu-page` ห้าม deploy ห้ามแตะ production ห้าม commit `docs/ai/scale-plu-prod.txt`

## 1) ตรวจสินค้าชั่ง (รายการตั้งต้น)
สินค้าชั่ง = สินค้าที่ **เปิดใช้งาน** และ (ชื่อมี ชั่ง/ซั่ง หรือมี PLU 800/801 อยู่แล้ว หรือ SKU เป็นเลข 80[01]xxx)
แต่ละตัวต้องจัดกลุ่ม:
- ✅ SKU จริง (ไม่ใช่เลข 80[01]xxx) เปิดใช้งาน มีราคา > 1 → ได้เลข PLU ใหม่
- ⚠️ SKU เป็นเลข 80[01]xxx เอง → ไม่แจกเลข แจ้ง "ต้องผูกกับ SKU จริงก่อน" ให้เลือก SKU ปลายทาง (picker) แล้วค่อยแจกเลข
- ⚠️ ราคา ≤ 1 → แจ้ง "ยังไม่ตั้งราคา" (แจกเลขได้แต่ติดธง)
- ⚠️ ชื่อซ้ำ/น่าจะเป็นสินค้าเดียวกัน (ชื่อหลังตัด `**`, ช่องว่าง, "ชั่ง กก", "(ชั่งน้ำหนัก)" ตรงกัน) → แจ้งให้เลือกตัวเดียว
- สินค้าปิดใช้งานไม่ได้เลข (แสดงในแท็บแยกเพื่อให้เปิดใช้งานถ้าตั้งใจ)

## 2) แผนรันเลข (preview ก่อน apply เสมอ)
- ปุ่ม "สร้างแผนเลขใหม่": เรียงตาม หมวดสินค้า แล้ว SKU (ให้สินค้ากลุ่มเดียวกันเลขติดกัน) แจก 801001, 801002, ... ข้ามเลขที่ผู้ใช้ล็อกไว้
- ตารางแผน: เลขใหม่ | PLU เดิม | SKU | ชื่อ | ราคา/กก. | ธงปัญหา — **แก้เลขใหม่รายแถวได้ในตาราง** (inline), ลากเรียง/ล็อกเลขได้ (อย่างน้อยแก้ตัวเลขตรงๆ + ปุ่มเรียงใหม่)
- ตรวจก่อน apply: เลขไม่ซ้ำ, อยู่ในช่วง 801000–801999, ทุก SKU ได้เลขเดียว, ไม่มีแถวติด ⚠️ ที่ยังไม่แก้ (หรือให้ติ๊กยอมรับ)
- **Apply** (ต้องยืนยัน + สิทธิ์จัดการข้อมูลหลัก) ใน transaction เดียว:
  - PLU เดิม 800/801 ทั้งหมดของสินค้าเหล่านั้น → `is_active = false` (ไม่ลบ เก็บประวัติ, ป้ายเก่าที่ค้างจะยิงไม่ได้ — แสดงคำเตือนนี้ก่อนกด)
  - สร้าง barcode ใหม่ type SCALE_PLU ใต้ SKU จริง
  - บันทึก audit (ใคร เมื่อไร เลขเก่า→ใหม่) + เก็บ "ชุดแผน" ไว้ย้อนดู/ยกเลิกได้ (rollback = เปิดเลขเก่า ปิดเลขใหม่)
- หลัง apply: ปุ่มดาวน์โหลด **ไฟล์ตั้งเครื่องชั่ง** CSV (PLU 6 หลัก, รหัสที่เครื่องชั่งใช้ = 3 หลักท้าย/5 หลักตามที่ป้ายใช้ `01xxx`, ชื่อสั้น, ราคา/กก., flag=8) + **PDF/HTML ป้ายทดสอบ** บาร์โค้ด EAN-13 ของทุก PLU ที่น้ำหนัก 1.000 กก. (ตรวจ check digit) สำหรับยิงทดสอบที่ POS
- กติกาเดิม attachPlu "ห้ามสร้าง PLU อัตโนมัติ" → เปลี่ยนเป็น: สร้างได้เฉพาะผ่านแผนรันเลขที่ผู้ใช้ยืนยันเท่านั้น (อัปเดต comment/ข้อความ)

## 3) หน้าตาแก้ไข/อัปเดตง่าย
- หน้าเดียว 3 แท็บ: **ตรวจสินค้าชั่ง** | **แผนรันเลขใหม่** | **PLU ปัจจุบัน** (หน้าที่ทำในรอบ 1)
- แก้ราคา ERP/กก. และราคาเครื่องชั่ง inline แล้วกด "บันทึกทั้งหมด" ทีเดียว, แถวที่แก้แล้วเปลี่ยนสี, ค้นหา/กรอง, ใช้บนจอ 1024 ได้
- ข้อความไทยทั้งหมด สั้น บอกวิธีแก้

## เทสต์ (ต้องผ่านทั้งหมด)
- จัดกลุ่มสินค้าถูกทุกกรณี; แผนแจกเลขเรียงไม่ซ้ำ; แก้เลขแล้วซ้ำ → apply ไม่ได้
- apply: เลขเก่าปิด, เลขใหม่อยู่ใต้ SKU จริง, POS หาเจอ (`/api/pos/products` คืน scale_plu ใหม่), rollback คืนสภาพ
- ป้ายทดสอบ check digit ถูก และถอดกลับด้วย profile POPSTAR-801 ได้ราคาถูก
- ถอดโค้ดหลักชั่วคราวแล้วเทสต์แดง
