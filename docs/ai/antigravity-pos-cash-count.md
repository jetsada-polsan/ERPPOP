## 1. วัตถุประสงค์และสรุปการดำเนินงาน

หน้านับเงินตอนปิดกะ (`FloatCloseDialog` ใน `apps/pos-python/pos_python/ui.py`) เดิมมีตาราง `self.coins` ซึ่งแคชเชียร์ต้องแตะช่องจำนวนแล้วพิมพ์ตัวเลขผ่านแป้น NumPad ทีละช่อง งานนี้ได้เพิ่มปุ่ม **`−`** และ **`+`** ในทุกแถวของชนิดเงิน เพื่อให้แคชเชียร์สามารถกดนับทีละใบ/เหรียญได้สะดวกรวดเร็วบนจอสัมผัส POS พร้อมปุ่ม **"ล้างทั้งหมด"** เพื่อรีเซ็ตค่าเป็น 0

### สิ่งที่ทำตามข้อกำหนด:
1. **ปุ่ม `−` และ `+` ในทุกแถวของตารางนับเงิน**:
   - จัดวางชิดช่องจำนวน: `[ − ]` อยู่ด้านซ้าย, `QLineEdit` อยู่ตรงกลาง, `[ + ]` อยู่ด้านขวา
   - ขนาดปุ่มแตะนิ้วได้สัมผัสชัดเจน (ขนาดอย่างน้อย 44×44 px ตามข้อกำหนด)
   - กด `+` → จำนวนเพิ่มทีละ 1 · กด `−` → จำนวนลดทีละ 1 โดยมีขอบเขตต่ำสุดที่ **0 (ห้ามติดลบเด็ดขาด)**
   - รองรับการกดค้าง (auto-repeat): ตั้งค่า `setAutoRepeat(True)`, `setAutoRepeatDelay(400)` (เริ่มช้า) และ `setAutoRepeatInterval(80)` (วนเร็วต่อเนื่อง)
   - กรณีช่องว่างหรือค่าที่ไม่ใช่จำนวนเต็ม (เช่น ข้อความว่าง `""`, ช่องว่าง `"   "`, หรือทศนิยม `"1.5"`) ระบบจะแปลงค่าฐานเป็น 0 ก่อนทำการบวกหรือลบ
2. **คงความสามารถในการพิมพ์ตัวเลขเองและใช้ NumPad ได้สมบูรณ์ 100%**:
   - ปุ่ม `+` / `−` ปรับค่าผ่าน `entry.setText(str(new_val))` ลงใน `QLineEdit` อินสแตนซ์เดิมโดยตรง
   - สัญญาณ `textChanged` จะยิงเข้า `self.denominations` เดิมเพื่อคำนวณยอดเงินของแต่ละแถวและยอดรวมตามระบบเดิมทุกประการ
3. **ปุ่ม "ล้างทั้งหมด" ใต้ตาราง**:
   - เพิ่มปุ่ม `self.clear_btn` ("ล้างทั้งหมด") ใต้ตาราง `self.coins`
   - เมื่อกด หากมีแถวใดที่มียอดนับอยู่ (> 0) จะแสดงกล่องยืนยันผ่าน `TouchMessage.question(self, "ยืนยันการล้างข้อมูล", "ต้องการล้างจำนวนเงินที่นับไว้ทั้งหมดเป็น 0 หรือไม่?")`
   - หากยืนยัน หรือกรณีทุกแถวเป็น 0 อยู่แล้ว จะตั้งค่าทุกแถวใน `self.coin_fields` เป็น `0`
4. **ความพอดีกับหน้าจอ POS (1024×768 และ 1366×768)**:
   - ปรับแต่งระยะ margin, padding, header, และ stepper ให้กะทัดรัดลง
   - ตาราง `self.coins` แสดงครบทั้ง **11 แถว** (1000, 500, 100, 50, 20, 10, 5, 2, 1, 0.50, 0.25) ใน viewport โดยไม่ต้องเลื่อน scrollbar (`viewport().height() >= 484px`)
   - ขนาดหน้าต่างไม่เกิน 900×680 px จึงไม่ล้นจอที่ความละเอียด 1024×768 และ 1366×768
   - ปุ่มทั้งหมดในหน้าต่างอยู่ภายในกรอบของหน้าต่าง (`top.y() >= 0` และ `top.y() + button.height() <= d.height()`) ผ่านการตรวจสอบ geometry test ทุกประการ
5. **ตรวจสอบหน้าเปิดกะ (`OpeningShiftDialog`)**:
   - หน้า `OpeningShiftDialog` ปัจจุบันมีเพียงช่องกรอกเงินทอนตั้งต้นช่องเดียว (`self.amount`) ไม่ได้มีตารางนับแบงก์ จึงไม่ต้องเพิ่มตามเงื่อนไขข้อ 5
6. **ชุดทดสอบครอบคลุม (`tests/test_cash_count_buttons.py`)**:
   - เพิ่มชุดทดสอบใหม่ 11 เทสต์ ครอบคลุม:
     - กด `+` เพิ่ม 1 และยอดรวมถูกต้อง
     - กด `−` ที่ 0 ยังคงเป็น 0 ไม่ติดลบ
     - กด `−` ลดค่าทีละ 1 จนถึง 0
     - ช่องว่าง/ทศนิยม/ตัวอักษร แล้วกด `+` ได้ 1, กด `−` ได้ 0
     - ปุ่มล้างทั้งหมดเมื่อเป็น 0 ไม่ต้องถามยืนยัน
     - ปุ่มล้างทั้งหมดเมื่อมีค่ายืนยันแล้วรีเซ็ตทุกแถวเป็น 0
     - ปุ่มล้างทั้งหมดเมื่อกดยกเลิก ค่ายังคงเดิม
     - คำนวณยอดเงินรวมถึงเศษสตางค์ถูกต้อง (เหรียญ 0.50 และ 0.25)
     - ตรวจสอบคุณสมบัติ auto-repeat (delay ≥ 200ms, interval ≤ 200ms)
     - ตรวจสอบขนาดปุ่มสัมผัสอย่างน้อย 44×44 px
     - ตรวจสอบตารางและปุ่มทั้งหมดพอดีกับหน้าจอ 1024×768 และเห็นครบ 11 แถว
