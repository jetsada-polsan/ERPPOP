## 1. ปัญหาที่พบและการแก้ไข (Issues & Solutions)

### 1.1 หัว Popup ไม่ทับเนื้อหาตอนเลื่อน (Modal Header Sticky & Scroll Padding)
* **ปัญหาเดิม:** เมื่อเปิดหน้าต่าง Popup เช่น หน้าบันทึกการแปรรูปสินค้า (`/stock-transforms`) หรือหน้าสร้างใบขอซื้อ/ใบจอง หัว Modal ที่มีแถบสลับโหมด "พื้นฐาน / ขั้นสูง" มีความสูงเพิ่มขึ้น เมื่อเลื่อนหน้าจอลงมากลางทาง หัว Modal จะทับช่องกรอกข้อมูล เช่น ช่อง **"สาเหตุสูญเสีย" ถูกตัดครึ่ง** และเมื่อกด Tab หรือโฟกัสช่องข้อมูล เบราว์เซอร์จะเลื่อนช่องขึ้นไปชนขอบบนสุดซึ่งถูกหัว Sticky บัง
* **การแก้ไข:**
  - กำหนดให้หัว Popup ทุกประเภท (`.booking-modal .modal-header`, `.po-modal > div:first-child`, `.cd-modal > div:first-child`, `.doc-modal .doc-titlebar`) มี `position: sticky !important; top: 0 !important; z-index: 50 !important;` พื้นหลังสีขาวทึบและมีเงาบางเบา (`box-shadow`)
  - เพิ่ม `scroll-padding-top: 104px !important;` บนกล่อง Scroll Container ของ Modal เพื่อให้การเลื่อนหน้าจอหรือโฟกัสช่องข้อมูลหยุดใต้แถบหัวพอดี
  - กำหนด `scroll-margin-top: 104px !important;` ให้กับทุกองค์ประกอบฟอร์มภายใน Modal (`.form-control`, `.form-select`, `.row`, `.loss-panel`, `.erp-has-float`)
  - ปรับแต่ง `.loss-panel` ในหน้าแปรรูปสินค้าให้เว้นระยะขอบ `margin-left: 0; margin-right: 0;` ไม่ขัดแย้งกับ Negative Margins ของ Bootstrap Row
  - ตรึงปุ่มบันทึกท้าย Modal (`.modal-footer`) ด้วย `position: sticky; bottom: 0; z-index: 40;` ไม่ให้เนื้อหาเลื่อนเลยทับปุ่มควบคุม

### 1.2 เอาตัวเลขนับตัวอักษรสีฟ้าออกทั้งระบบ (Remove Character Counters)
* **ปัญหาเดิม:** มีตัวเลขนับตัวอักษรสีฟ้า (เช่น `500`, `465`) แสดงอยู่มุมขวาบนของช่องข้อความ รกสายตาและบางครั้งทับซ้อนกับป้ายชื่อหรือไอคอน
* **การแก้ไข:**
  - ปรับปรุงฟังก์ชัน `enhanceFloatingFields` ใน [`public/js/peak-style-ui.js`](file:///Applications/MAMP/htdocs/erp/ERPPOP/public/js/peak-style-ui.js) โดยไม่สร้างองค์ประกอบ `.erp-fl-counter` เข้าไปใน DOM อีกต่อไป
  - ลบแท็ก `<span class="erp-fl-counter">` ในคอมโพเนนต์ Blade [`resources/views/components/erp-input.blade.php`](file:///Applications/MAMP/htdocs/erp/ERPPOP/resources/views/components/erp-input.blade.php)
  - ซ่อนคลาส `.erp-fl-counter { display: none !important; }` ใน [`public/css/peak-style-ui.css`](file:///Applications/MAMP/htdocs/erp/ERPPOP/public/css/peak-style-ui.css) เป็นแนวป้องกันเสริม
  - รักษาแอตทริบิวต์ `maxlength` ของ HTML ไว้ตามเดิม เพื่อจำกัดความยาวของข้อความได้อย่างปลอดภัย

### 1.3 หน้าจอแปรรูปสินค้า แสดงหน่วยนับชัดเจนทุกช่อง (Stock Transforms Units)
* **ปัญหาเดิม:** ตารางวัตถุดิบและผลผลิตไม่แสดงหน่วยนับให้ผู้ใช้ทราบว่าตัวเลขที่กรอกคือหน่วยอะไร (เช่น กรอกเลข 3 แต่ไม่รู้ว่าคือ 3 กก. หรือ 3 กล่อง) ทำให้ผู้ใช้งานสับสน
* **การแก้ไข:**
  - เพิ่ม Add-on แสดงหน่วยนับต่อท้ายช่องกรอกจำนวนทุกช่องด้วย Bootstrap Input-Group เช่น `[ 3 ] [ กล่อง ]` หรือ `[ 30 ] [ กก. ]`
  - ปรับปรุงหัวตารางคอลัมน์ให้ระบุหน่วยนับและหน่วยเงินชัดเจน:
    - **วัตถุดิบ:** `สินค้าวัตถุดิบ` | `จำนวนใช้จริง` | `ทุนเฉลี่ยระบบ` (แสดง บาท/หน่วย) | `ต้นทุนรวม (บาท)`
    - **ผลผลิต:** `สินค้าผลผลิต` | `น้ำหนักชั่งได้จริง` | `ต้นทุนผลผลิต` (แสดง บาท/หน่วย) | `Yield (%)`
  - ปรับปรุง JavaScript ใน `onProductPicked()` และ `loadRecipe()` ให้เก็บค่า `unit_name`, `sku_code`, และ `name_th` แสดงผลคู่กับจำนวนเสมอ
  - ปรับปรุงหน้าแสดงรายละเอียด [`resources/views/stock-transforms/show.blade.php`](file:///Applications/MAMP/htdocs/erp/ERPPOP/resources/views/stock-transforms/show.blade.php) ให้แสดงหน่วยนับต่อท้ายจำนวนและต้นทุนอย่างเป็นระเบียบ

## 3. ส่งต่อ Claude: เรื่องหน่วย / Yield ในหน้าแปรรูปสินค้า

### 3.1 สาเหตุที่ Yield ขึ้น 1,000%
จากการตรวจสอบโค้ดในหน้าจอ [`resources/views/stock-transforms/index.blade.php`](file:///Applications/MAMP/htdocs/erp/ERPPOP/resources/views/stock-transforms/index.blade.php) พบจุดที่เป็นสาเหตุของตัวเลข Yield 1,000% ดังนี้:

1. **การคำนวณน้ำหนักวัตถุดิบขาเข้า (`syncInputWeight`):**
   ```javascript
   syncInputWeight() {
       this.inputWeight = Math.round(this.rawItems.reduce((s, i) => s + (Number(i.qty) || 0), 0) * 10000) / 10000;
   }
   ```
   โค้ดปัจจุบันนำฟิลด์ `item.qty` มารวมกันตรงๆ โดยถือว่าผลรวมนี้คือ **น้ำหนักวัตถุดิบในหน่วยกิโลกรัม (`inputWeight`)** เสมอ

2. **การคำนวณ Yield (`yieldPercent`):**
   ```javascript
   yieldPercent(item) {
       const output = Number(item.qty) || 0;
       return this.inputWeight > 0 ? this.money(output * 100 / this.inputWeight) + '%' : '-';
   }
   ```
   เมื่อผู้ใช้งานหยิบวัตถุดิบที่เป็นหน่วย **"กล่อง"** หรือ **"แพ็ค"** เช่น หมูสามชั้น 3 กล่อง (ซึ่ง 1 กล่องมีน้ำหนัก 10 กก. รวมเป็น 30 กก.) แต่ในช่องจำนวนใส่เป็น `3` ระบบจะคำนวณได้ `inputWeight = 3`  
   จากนั้นเมื่อนำไปแปรรูปได้เนื้อตัดแต่งผลผลิตออกมา **`30 กก.`** โค้ดจะนำ `(30 * 100) / 3 = 1,000%` ทันที

3. **ผลกระทบด้านต้นทุนและการดูดซับส่วนสูญเสีย (`lossCost`):**
   สูตร `lossWeight = inputWeight - outputWeight` จะได้ `3 - 30 = -27` ทำให้ระบบมองว่าไม่มีการสูญเสีย หรือคำนวณต้นทุนต่อหน่วยผิดพลาดหากหน่วยนับของวัตถุดิบและผลผลิตไม่แปลงเป็นฐานเดียวกัน (Base Unit / Weight Ratio)

### 3.2 ข้อเสนอแนะแนวทางแก้ไขสำหรับ Claude
1. **เพิ่มการดึงอัตราส่วนแปลงหน่วย (`unit_multiplier` หรือ `weight_per_unit`):**
   ในตาราง `products` และ `product_units` ควรมีฟิลด์น้ำหนักต่อหน่วยมาตรฐาน (เช่น 1 กล่อง = 10.00 กก.) เมื่อผู้ใช้เลือกสินค้าวัตถุดิบ ให้คำนวณ `raw_item_weight = item.qty * item.weight_per_unit`
2. **ปรับปรุง Service ฝั่ง Backend (`StockTransformService`):**
   ตรวจสอบว่าการบันทึกการตัดสต็อกวัตถุดิบ (Stock Movement) จะต้องตัดตามหน่วยขาย/จัดเก็บ (กล่อง) แต่น้ำหนักในการคำนวณ Yield และกระจายต้นทุน (Cost Absorption) ต้องแปลงเป็นหน่วยมาตรฐานกิโลกรัมก่อนเสมอ
3. **ป้องกัน Yield ติดลบหรือเกินขอบเขต:**
   ในหน้าฟอร์มควรมี Validation ตรวจสอบ หาก Yield เกิน 100% หรือผิดปกติมาก ให้ระบบแจ้งเตือนว่าหน่วยนับวัตถุดิบกับผลผลิตอาจไม่ตรงกัน
