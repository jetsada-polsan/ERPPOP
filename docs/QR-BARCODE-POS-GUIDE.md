# คู่มือ QR Code และ Barcode สำหรับ POPSTAR ERP/POS

เอกสารนี้ครอบคลุมการเตรียมข้อมูล การพิมพ์ฉลาก การขายหน้าร้าน การรับเข้า/นับสต็อก และการแก้ปัญหา
สำหรับระบบ Web/PWA ที่ใช้งานบนคอมพิวเตอร์ Android และ iPhone

## 1. หลักการข้อมูล

- `SKU` เป็นรหัสหลักของสินค้า เช่น `FM-HK-CR35`
- Barcode เก็บเป็นรหัสค้นหา ไม่ฝังราคาและสต็อก เพราะราคาและสต็อกเปลี่ยนได้
- QR เก็บ SKU หรือ URL สั้นของสินค้าเท่านั้น
- Barcode ในฐานข้อมูลต้องไม่ซ้ำ ระบบค้นหา barcode ก่อน แล้วจึง fallback ไปค้นหา SKU
- ถ้าสินค้าไม่มี barcode ให้ใช้ SKU ยิงด้วยเครื่องสแกนหรือพิมพ์ในช่องค้นหาได้

ชนิดที่รองรับ: `Code128`, `Code39`, `EAN-13`, `QR Code` รวมถึง barcode เครื่องชั่งเดิมของระบบ

## 2. เตรียมระบบก่อนใช้งาน

### ผู้ดูแลระบบ

1. ตรวจว่าเว็บไซต์เปิดด้วย `https://` หรือ `http://localhost` เท่านั้น
2. ติดตั้ง dependency ของโปรเจกต์ด้วย `composer install` และ `npm install`
3. รัน migration ด้วย `php artisan migrate` หลังสำรองฐานข้อมูลแล้ว
4. สร้าง frontend ด้วย `npm run build`
5. ตรวจสุขภาพด้วย `php artisan erp:health`
6. ล้าง cache ตามขั้นตอนใน `docs/OPERATIONS.md` เมื่อ deploy เวอร์ชันใหม่

ระบบจะสร้างตาราง `product_scan_logs` สำหรับบันทึก context, รหัสที่ยิง, แหล่งที่มา, ผลลัพธ์,
ผู้ใช้งาน, สาขา และสินค้า โดยไม่เก็บภาพจากกล้อง

### ความปลอดภัย

- เบราว์เซอร์จะขอสิทธิ์กล้องเมื่อกดปุ่มสแกนเท่านั้น
- กล้องทำงานในเครื่องผู้ใช้ ภาพไม่ถูกส่งไปยังเซิร์ฟเวอร์
- ปิดหน้าต่างหรือออกจากหน้าแล้วระบบสั่งหยุดกล้อง
- ห้ามใช้ HTTP จริงกับ production เพราะข้อมูล session/token อาจรั่ว
- ถ้าปฏิเสธสิทธิ์กล้อง ให้ใช้การกรอกรหัสหรือเลือกภาพแทน

## 3. ตั้งค่าข้อมูลสินค้า

1. เปิดเมนูสินค้าและเลือกสินค้า
2. เพิ่ม Barcode ที่ช่อง barcode โดยเลือกชนิดให้ตรงกับฉลาก
3. ตรวจว่ารหัสไม่ซ้ำกับสินค้าอื่น
4. ถ้าไม่มี barcode ให้ใช้ SKU เป็นรหัสสำหรับค้นหา
5. อย่าเปลี่ยนราคาหรือต้นทุนผ่านข้อมูล barcode

### การพิมพ์ฉลาก

1. เปิดเมนูพิมพ์ป้ายราคา
2. เลือก template และสินค้า
3. กำหนดจำนวนฉลากต่อสินค้า
4. เปิด preview แล้วตรวจชื่อ, SKU, barcode, QR, ราคา และหน่วย
5. กดพิมพ์ โดยหน้ากระดาษ A4 จะจัดช่องฉลากให้อัตโนมัติ

Code128 เป็นค่าเริ่มต้นสำหรับ SKU ทั่วไป หากต้องใช้ EAN-13 ต้องเป็นเลข 13 หลักและ check digit ถูกต้อง

## 4. ขายหน้าร้านบน POS

### กล้องมือถือ/เว็บแคม

1. เปิดหน้า POS ผ่าน HTTPS
2. กดปุ่ม **สแกน** ข้างช่องค้นหา
3. กด **เริ่มสแกน** และอนุญาตกล้อง
4. หันกล้องหลังไปที่ QR หรือ barcode ให้เห็นชัดในกรอบ
5. เมื่อพบสินค้า ระบบจะเพิ่มเข้าตะกร้าอัตโนมัติ พร้อมเสียง/สั่นแจ้งเตือน
6. ใช้ **หยุด**, **เปลี่ยนกล้อง** หรือ **ปิด** ตามต้องการ

ระบบกันการอ่านรหัสเดิมซ้ำภายใน 1 วินาที หากไม่พบสินค้าให้ตรวจรหัสแล้วลองใหม่

### เครื่องสแกน USB/Bluetooth

1. เชื่อมต่อเครื่องสแกนให้ระบบปฏิบัติการเห็นเป็น keyboard
2. คลิกช่องค้นหา POS
3. ยิง barcode หรือ SKU แล้วให้เครื่องส่ง Enter ต่อท้าย
4. ระบบค้นหา barcode ก่อน และใช้ SKU เป็น fallback

### กรอกด้วยมือ/สแกนจากรูป

ในหน้าต่างสแกนสามารถกรอก Barcode/SKU แล้วกด Enter หรือเลือกภาพจากมือถือเพื่ออ่านแทนกล้องได้

## 5. รับเข้าและปรับสต็อก

1. เปิดหน้า Warehouse Mobile
2. เลือก รับเข้า, รับตามใบสั่งซื้อ, ตรวจยอด หรือ นับสต็อก
3. ยิง barcode/QR หรือพิมพ์ SKU
4. ตรวจชื่อสินค้า, หน่วย, ต้นทุนเดิม และยอดคงเหลือ
5. กรอกจำนวนจริงแล้วบันทึก
6. ยิงรายการถัดไปต่อได้โดยไม่ต้องโหลดหน้าใหม่

การสแกนเป็นเพียงการค้นหาสินค้า ไม่เปลี่ยนราคาและไม่ตัด/เพิ่มสต็อกจนกว่าผู้ใช้จะกดบันทึกเอกสาร

## 6. API และ audit

ระบบเดิมมี endpoint ค้นหาสินค้า POS แบบ exact match และ endpoint scan ของ POS ซึ่งคืนสินค้า,
หน่วย, ราคา POS และสต็อกล่าสุดจากเซิร์ฟเวอร์ การบันทึกการขาย/รับเข้ายังคงผ่าน service เดิม
เพื่อรักษากฎตัดสต็อกและบัญชี

ทุก scan ที่ผ่าน endpoint POS จะถูกบันทึกใน `product_scan_logs` โดย `result` หลักคือ `matched`
หรือ `not_found` และ `source` คือ `camera`, `image`, `keyboard` หรือ `manual`

## 7. ข้อมูลทดสอบที่แนะนำ

| กรณี | ค่า |
|---|---|
| สินค้าทดสอบ | SKU `FM-HK-CR35` |
| Barcode | `FM-HK-CR35` แบบ Code128 |
| QR | ค่า `FM-HK-CR35` หรือ URL สั้นของสินค้า |
| ไม่มี barcode | สินค้าที่มี SKU แต่ไม่มีแถวใน `product_barcodes` |
| ไม่พบสินค้า | `NOT-FOUND-0001` |

ใช้ข้อมูลทดสอบแยกจากข้อมูลขายจริง และห้ามใช้ migration/seed ที่ลบข้อมูลเดิม

## 9. แก้ปัญหาเร็ว

**ปุ่มกล้องไม่ทำงาน**: ตรวจ HTTPS, สิทธิ์กล้องของเว็บไซต์, กล้องไม่ถูกใช้โดยแอปอื่น และลองช่องกรอกมือ

**สแกนได้แต่ไม่พบสินค้า**: ตรวจว่ารหัสตรงกับ `product_barcodes.barcode` หรือ `products.sku_code`,
ตรวจสินค้า active และตรวจว่าสาขาถูกต้อง

**ฉลากอ่านไม่ได้**: พิมพ์ที่ 100% scale, อย่าย่อหน้าเว็บ, ใช้ Code128 สำหรับ SKU ที่มีตัวอักษร และเว้นขอบฉลาก

**รับเข้าแล้วสต็อกไม่เปลี่ยน**: ตรวจว่ากดบันทึกเอกสารสำเร็จ ไม่ใช่เพียงสแกนค้นหา และตรวจสถานะอนุมัติของเอกสาร

**กล้องยังมีไฟค้าง**: ปิดหน้าต่างสแกนหรือออกจากหน้า แล้ว reload หนึ่งครั้ง; โค้ดจะเรียก `stop()` และ `clear()`

## 10. ขอบเขตการทดสอบรอบนี้

ตรวจ build frontend และ syntax แล้ว แต่การทดสอบ Laravel เต็มชุดต้องทำในเครื่องที่ติดตั้ง Composer dependencies
ครบ เนื่องจาก checkout สำหรับพัฒนานี้ไม่มี network ไป Packagist/GitHub ระหว่างติดตั้ง `vendor`.
การทดสอบกล้อง, iPhone Safari, Android Chrome, เครื่องสแกนจริง และเครื่องพิมพ์ A4 ต้องทำเป็น UAT บนอุปกรณ์จริง
ก่อนเปิด production.
